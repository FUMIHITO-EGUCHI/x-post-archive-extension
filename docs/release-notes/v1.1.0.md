# v1.1.0

CWS 初公開（v1.0.0）以降に積み上げた、大規模アーカイブ向けのパフォーマンス改善・自動保存の取りこぼし修正・障害時の復旧導線をまとめたリリース。X 側の「履歴」ハブ統合への追従も含みます。

## ユーザーにとって良くなったこと

- **X の「履歴」ページで一括取り込みが使えるようになりました**: X が「いいね」タブと「ブックマーク」を履歴ハブへ統合した結果、一括取り込みボタンが表示されなくなっていました。`/i/history`（ブックマーク）と `/i/history/likes`（いいね）に追従し、タブを切り替えるとボタンも入れ替わります
- **画像を拡大表示したまま「いいね」しても保存されるようになりました**: 画像 lightbox から付けた「いいね」は X 自身の service worker からリクエストが飛ぶため、ページ側の監視から見えず自動保存が発火していませんでした
- **一部の投稿が原因で自動保存が止まる問題を修正**: 壊れた overlay 記事が混ざるとスレッド走査が例外で落ち、以降その画面での自動保存が丸ごと停止していました
- **大規模アーカイブの viewer が軽くなりました**: 1〜2万件規模で、ページ送りのたびに posts テーブル全件を走査していた処理を索引だけで済むよう変更。スクロール・並び替え・削除時の再描画も削減しています
- **拡張機能が応答しなくなったとき、viewer から再起動できるようになりました**: バックグラウンドが固まって全クエリがタイムアウトした場合に、再起動を促す導線が出ます
- **保存中に誤って「再起動」を促されなくなりました**: 一括保存など正当に時間のかかる処理と、本当に固まっている状態を区別するようになりました。再起動ボタンには「進行中の保存が中断される」旨を明記しています
- **保存の取りこぼしが後から追えるようになりました**: 「いいねしたのに保存されていない」ケースの原因が診断ログに残ります
- **ディスク書き込みが減りました**: デバッグログの重複永続化を抑制し、IndexedDB への書き込み churn を削減しています

> **初回起動時のマイグレーションについて**: DB スキーマを v18 → v19 に更新します。既存の全投稿レコードを1度書き換えるため、アーカイブ件数によっては初回の viewer 起動に時間がかかることがあります。

## 修正内容

### X 追従

- **履歴ハブ対応 (#130)**: 一括取り込みの表示判定を `/i/history` / `/i/history/likes` に更新。旧 URL（`/i/bookmarks`、`/<username>/likes`）はリダイレクト完了前の一瞬に備えて判定に残置。2つの判定が同一 URL に同時マッチしないことをテストで固定。実機調査は `docs/findings/2026-08-22-x-history-hub.md`
- **lightbox からの like 救済 (#128)**: MAIN world の fetch/XHR interceptor では観測できない X service worker 発のリクエストに対し、`webRequest` ベースの fallback observer を追加。interceptor 側はレスポンス payload まで検証するため primary のまま、fallback は遅延 + 重複排除で二重保存を防止
- **スレッド走査のクラッシュ回避 (#128)**: 壊れた overlay 記事をスキップし、走査全体が落ちないよう変更

### パフォーマンス

- **posts 全表スキャンの排除 (#120)**: DB スキーマ v19 で `thread_root_id` を正規化（単発投稿は自身の id を保持）し、null キーが索引から除外される IndexedDB の性質を回避。ルート/単発の判定を `orderBy("thread_root_id").uniqueKeys()` に、メンバー→ルートの解決を新設の `[x_post_id+thread_root_id]` 複合索引に置き換え、ページ取得ごとの全件走査と全レコード bulkGet を撤廃。マイグレーションを経由しない書き込み（v19 以前のバックアップ復元）向けに索引のみの self-heal fallback を用意
- **viewer 描画 quick wins (#119)**: ThreadCard の memo 化、`Intl` フォーマッタのキャッシュ、`refetchStatus` の等価比較、削除のローカル反映

### 安定性

- **runtime liveness ping (#117)**: 30 秒タイムアウト単独では「SW 凍結」と「SW 多忙」を区別できず、健全な SW に対して再起動ボタンが出てクリックで進行中の保存が中断される問題を修正。`runtime/ping` を追加し、background は他の処理より前に即応答する。viewer はタイムアウト時に 3 秒タイムアウトの ping を送り、無応答のときだけ再起動を提案する
- **拡張再起動の導線 (#114)**: runtime リクエストがタイムアウトしたとき、viewer から拡張機能を再起動できるようにした
- **logger の永続抑制 (#113 / #118)**: デバッグログの重複永続化を抑制。rollup 欠如・clear バースト・時計逆行・persist 失敗時の窓消費といった取りこぼしも塞いだ

### 可観測性

- **保存経路の計測 (#126)**: `traceId` を保存経路全体に通し、like/bookmark の取りこぼしと各段階のタイミングを永続ログ化。取りこぼしは操作名と失敗理由のみを記録し、投稿 ID・リクエストボディ・クエリ文字列は残さない

### 設定 UI

- 「ブックマークした投稿を保存」に、環境によってはタイムラインにブックマークボタンが出ないことと、その場合の代替導線を注記（`aria-describedby` でスクリーンリーダーにも伝達）
- 一括取り込みの duplicate-only batch 閾値の説明を「X の履歴ページ」表記へ更新
